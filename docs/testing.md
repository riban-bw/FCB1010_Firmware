# What has and has not been tested

[Back to the README](../README.md)

Tested:
- The controller logic: stomp toggling, all four pedal modes, CC, note and program change footswitch messages and the footswitch editor (typed and pedal values, accept, revert, saved records), program change on release with auto-repeat, program mode (programs chosen and typed on the footswitches, ENTER, ESCAPE, no repeat while typing), the UP + DOWN chord, every configuration page and its saved bytes, pedal scaling, hysteresis, expression pedal pickup (waiting, the distance shown and its timeout, the EXP LED flash rate, picking up within the window or by passing the value, values from MIDI IN and footswitches, a full MIDI OUT at the pickup, the pedal pages' pickup switch and its saved bit, NRPN 94 / 95), calibration flow, a full MIDI buffer, bad input, and MIDI IN parsing including running status, split messages, real-time bytes, SysEx, other channels and the 63/64 threshold, plus the momentary long-press behaviour: every switch, two switches at once, duplicate or unmatched hold and release events, a full MIDI queue at press and at release, calibration, and incoming MIDI CC changes during a hold (`make test`).
- The settings EEPROM code (`src/eeprom.inc`, the same code the firmware runs) against a bit-level model of the 24C16 (`test/test_eeprom.c`, in `make test`): its bit-banged I2C, every record of every bank saved, read back and loaded without overwriting another, writes split at the 16-byte page boundaries, the write-cycle wait, and erased, corrupted and moved records refused. The model follows the 24C16 data sheet as the code assumes it; a real chip has not been tried.
- The browser editor, which runs the same control code, with a scripted smoke test (`make editor`), including its MIDI configuration panel driving the emulated pedal (Find, read, set, save, discard).
- The expression pedal pages (pages 3 and 4, the same footswitches for each pedal: pickup toggles, the CC shown before its editor opens, the calibration started by footswitch 9 and stepped by UP and DOWN (the live value, `Lo`, the heel, `Hi`, the toe, DOWN cancelling or going back, footswitches and holds ignored meanwhile) and its timed `Er`, footswitches acting on release only with UP and DOWN up), its CC editor (typed values, pedals ignored, short UP keeps, short DOWN puts back), relays moved only by a change of their triggers, not by a bank change, page 1 showing a footswitch's settings in turn, the footswitch editor (pedal mode, type, number and values in order, UP on the OFF value keeping and DOWN on the pedal mode putting everything back, long presses acting as short ones), the shared number entry (dim digits that can come next, the flashing dot, UP and DOWN ending or cancelling a number without changing page), dim LEDs, page 9's lamp test, chase and footswitch 10, the SysEx Identity Request, page 7's `Pr` and program in turn, the save-to-bank prompt (its number and dot alternating), the flashing dot while a number is typed, the MIDI FUNCTION flash for sent MIDI, the pentatonic note banks, the editor page's Copy bank and Paste bank, and the pedal mode words on page 1 (`St`, `+St`, `Pu`, `-Pu`; the signs are drawn only by the editor, see below).
- The misc page (the clock display, running status and active sensing toggles, active sensing's timing, saved, loaded and cancelled), the visual metronome from MIDI Start, Continue, Stop, clock and Song Position Pointer (beat 1's `+` and the other beats' `-`, run mode only), running status on MIDI OUT, the dim LEDs of the SWITCH pages, and the identity sent at power-on (`make test`, `make editor`; the identity also in the simulator).
- Configuration over MIDI in the controller logic: every parameter, the dump and its pacing, a dump fed back in, selection and deselection, the commands, and the run-mode-only rule (`make test`).
- Footswitch banks in the controller logic: each bank's own relays, pedal controllers and pickup responses (saved, loaded and changed with the bank, a pickup pedal waiting for a new controller's value), choosing with UP / DOWN in bank mode, the default (taps, held repeat, ends), states carried over by CC and note (nothing sent), resting states of the rest, program change switches, holds and pending reverts across a change, saving and comparing the bank in use, and the bank parameter over MIDI (`make test`); shared CC and note states within a bank (`make test`); in the editor and its configuration panel (`make editor`); and in the simulator, with the stack depth of the EEPROM reads (`test/sim_smoke.sh`).
- The real 8051 image in a simulator: key scan and debounce, toggle on and off, bank changes from UP and DOWN with the held repeat, MIDI UART output with the correct bytes, the UP + DOWN chord opening and closing configuration mode (read back from RAM, including the stack depth of the save path), the long-press behaviour just under (stays latched) and just over (reverts) the long-press time, the power-on and page 9 LEDs and display, and the stack under receive load (`test/sim_smoke.sh`).
- **The "+" and "-" on the display's left position** (the pickup distance, and the `+St` and `-Pu` pedal modes), and the letters S, small r and small u. Which segment bits drive the signs is a guess (`SIGN_MINUS` / `SIGN_PLUS` in `src/hw.c`); the reference library does not draw them.
- **Everything on an actual FCB1010** (see [Hardware notes](technical.md#hardware-notes)).
- The pedal ADC reading and the EEPROM calibration and settings save and load. The settings records are tested against a model of the EEPROM only, and the simulator does not model it. The code is adapted from the same library.
- **The 0.6 second long-press threshold on real hardware.** It is counted from the 2ms scan timer, which assumes a 12MHz crystal. The simulator measures it correctly in simulated time, but a different crystal speed or a slower scan would shift it.
- The 31250 baud MIDI rate on real silicon. It is computed for a 12MHz crystal; the simulator confirms the bytes but not the timing.

Not tested, because it needs real hardware:

- **MIDI IN on the real image.** The simulator's UART input would not deliver bytes to the firmware. The parser is tested on the host, and the simulator confirms the receive interrupt queues and drains bytes without disturbing key handling or the stack, but the step from a received byte to a lit LED has not been run end to end on the 8051 image. The FCB1010's MIDI IN feeds the same UART, per the reference code, which receives SysEx through it.
- The dim LEDs' brightness (a short part of each 2ms LED slot), and the metronome's `-` / `+`, which uses the same unconfirmed sign segments as the pickup distance.
- The configuration panel with a real pedal and MIDI interface. Its editor target is tested, and so is its Web MIDI code against a simulated interface, but not with a real one.

A wrong LED or key map does no electrical harm, but it will look wrong.
